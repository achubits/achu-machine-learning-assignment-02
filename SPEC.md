# Project Specification

## Goal

Classify breast tumours as malignant or benign from 30 cell-nucleus measurements, compare five classifiers on one hold-out test set, and provide a Streamlit app that evaluates the saved models on uploaded test data. Academic use only.

## Assignment Requirements and How They Are Met

| Requirement | Implementation |
|---|---|
| Public dataset, at least 500 rows and 12 features | Breast Cancer Wisconsin (Diagnostic), UCI/Kaggle: 569 rows, 30 features |
| Logistic Regression, Decision Tree, KNN, Naive Bayes, SVM on the same data | `train_models.py`; GaussianNB and RBF `SVC`; one shared split |
| Accuracy, AUC, Precision, Recall, F1, MCC per model | `ml_utils.score_metrics`, positive class = Malignant |
| `app.py`, `requirements.txt`, `README.md`, `test_data.csv`, `model/` | All present; `model/` and `test_data.csv` generated by training |
| README sections a-d with comparison table, observations and winner | README; results block generated by `train_models.py` |
| App: CSV upload, model dropdown, metrics, confusion matrix/report | `app.py` sidebar and *Model performance* tab |
| App loads saved models and does not retrain | `joblib.load` + `predict_proba` only |
| Results of the different models visible in the app | *Compare all models* tab |
| GitHub, Streamlit Cloud deployment, BITS Lab screenshot, PDF | User-owned steps |

## Data Contract

- Source file `breast_cancer.csv`: columns `id`, `diagnosis`, 30 numeric features, and an empty trailing column that is dropped on load.
- Target `diagnosis`: `M` → Malignant (positive), `B` → Benign. `Malignant/Benign` and `1/0` are also accepted.
- `id` is never a feature. Uploaded files may contain extra columns; they are ignored.

## Modelling Contract

- One stratified 80/20 split, seed 711 (455 train / 114 test). The test rows are written unchanged to `test_data.csv`.
- Each model is a pipeline: median imputer → standard scaler → classifier, fitted on training rows only.
- Hyperparameters chosen by 5-fold stratified grid-search CV on the training set, scoring MCC.
- Test metrics are computed by re-reading `test_data.csv` through the same `evaluate_frame` function the app uses, so the README and app show identical numbers.
- AUC uses predicted probabilities. Other metrics use threshold 0.5. Winner = highest test MCC, ties broken by AUC and then CV MCC.

## App Behaviour

- Sidebar: CSV upload, bundled-test-file switch, test-file download, model dropdown with tuned settings, decision threshold slider (default 0.5).
- Tabs: Model performance (six metrics, confusion matrix, ROC, probability distribution, classification report); Compare all models (table, bar chart, ROC overlay, five confusion matrices); Predictions (per-row table, errors filter, CSV download); Data overview.
- Clear errors for missing columns, unknown target values, single-class files, unreadable CSVs and missing model files. A warning is shown if the runtime scikit-learn version differs from the training version.

## Constraints

- No dataset downloads or package installs without the user's approval; training and app testing happen in Colab, BITS Virtual Lab and Streamlit Cloud.
- Never fabricate metrics: README results are written only by `train_models.py`.
- User-provided text shown in custom HTML is escaped.

## Acceptance Criteria

1. `pytest -q` passes.
2. `python train_models.py` writes five `.joblib` pipelines, `model_registry.json`, `test_data.csv`, reports, and fills the README results block.
3. `streamlit run app.py` evaluates `test_data.csv` with every model and the numbers match the README at threshold 0.5.
